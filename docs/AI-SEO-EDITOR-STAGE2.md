# AI SEO Editor — этап 2 (Timeweb Cloud)

## Назначение

Доработка интегрируется поверх существующего БАР и **не заменяет** его методы извлечения страниц, подсчёта частот или работы с XMLRiver. Исходный проект и его лицензия сохранены. Правки подготовлены на основе этапа 1, предоставленного владельцем репозитория.

Рабочий процесс:

1. Написать готовую статью по регламенту контент-фабрики 13.3.
2. Открыть `/analyzer`, выбрать существующий режим `Вставить текст` для VC.ru/Состав либо `По URL` для собственной страницы и получить ТЗ.
3. Нажать `Открыть в редакторе` (или вручную загрузить Markdown-файл и отчёт).
4. Выбрать сферу `VC.ru / Состав` или `Собственный сайт`.
5. Ввести пароль редактора, нажать `ИИ-разбор следующих 25`; принять/изменить решения.
6. Нажать `Предложить замены`; оценить и подтвердить **каждую** предлагаемую замену.
7. Скачать изменённую статью `bar-editor-article-revised.md`.
8. Отправить новую версию на повторный анализ БАР, проверить качество и только после этого разместить её на площадке.

## Два режима источника в БАР

Это функция **самого БАР**, а не новый парсер AI-редактора:

- `Вставить текст`: БАР анализирует введённый текст статьи. В editor передаются и отчёт, и исходный текст.
- `По URL`: БАР анализирует доступную по URL страницу. В editor передаётся отчёт и признак источника URL. Для AI-редактирования необходимо отдельно вставить/загрузить управляемый текст из CMS: БАР не передаёт из своего отчёта редактируемый полный HTML/Markdown. Для фактического измерения изменений по URL их сначала надо опубликовать.

Режим редактора `publication` включает зоны `Title`, `H1`, `Text`, `H2–H6`; отчёт «Общее» и `A` (глобальные анкоры чужой платформы) не передаются ИИ. Режим `site` включает все зоны. Статистика всех зон остаётся доступна для просмотра вручную.

## Настройка Timeweb

В приложении Timeweb Cloud откройте настройки переменных окружения/секретов и задайте:

```
OPENAI_API_KEY=<ключ OpenAI API>
OPENAI_MODEL=gpt-6-luna
EDITOR_ACCESS_TOKEN=<длинный случайный секрет>
```

- `OPENAI_API_KEY` — отдельный оплачиваемый API-ключ OpenAI, не логин ChatGPT и не XMLRiver.
- `OPENAI_MODEL` можно заменить моделью, доступной вашему проекту OpenAI. Дешёвый вариант по умолчанию — `gpt-6-luna`.
- `EDITOR_ACCESS_TOKEN` — созданный **вами** случайный пароль редактора (минимум 24+ случайных символа рекомендуется). Вводится также в редакторе в поле «Пароль AI-редактора».
- Значения **не вносятся в GitHub**, не пишутся в `.env.example` и никогда не именуются `NEXT_PUBLIC_*`.
- После изменения переменных перезапустите/переразверните приложение, если Timeweb не обновляет env у работающего контейнера автоматически.

API `/api/editor/assist` закрыт паролем: без обеих серверных переменных возвращает 503, неверный пароль — 401. Данные отправляются в OpenAI **только при явном действии** и только в пределах текущей порции. Не публикуйте пароль в репозитории и не пересылайте третьим лицам. Используйте квоты и лимиты расходов на стороне OpenAI.

## Состав этапа

- Парсер ТЗ — без изменений, обрабатывает зоны и 661+ рекомендаций.
- Пакетная AI-классификация — до 25 рекомендаций за запрос; показывает причины и предложения.
- Консервативная редактура — до 6 точных замен за запрос, без автоматического изменения документа.
- Замена проверяется по точному совпадению исходного текста, отсутствию дубликата и сохранению URL. Правки в заключительный блок `## Ключевые слова` блокируются.
- После принятой замены показатели старого ТЗ помечаются устаревшими.
- Скачивание исправленного Markdown, решений по рекомендациям.

**Не реализовано на этом этапе:** полноценный цикл автоматического повторного запуска БАР, автопубликация в VC или WordPress, история проектов в БД, автоматическая фактическая веб-проверка условий, режим массовой переработки 661 рекомендаций без участия пользователя.

## Ограничения

- Длинная статья (70 тыс. символов максимум для ИИ-запроса), одна порция 25 рекомендаций; лимиты предохраняют стоимость.
- Дополнительные правила максимум 14 тыс. символов. В серверной инструкции встроено компактное ядро регламента 13.3. Полная версия регламента не загружается на сервер автоматически.
- Строгая структурированная выдача помогает не терять идентификаторы, но ошибки смысла возможны. Всё требует редакторского контроля.
- Любая правка статьи меняет основания для прежних числовых выводов БАР. Метрики «после» считаются только **новым запуском БАР**, а не моделью.
